# 카드 랩 · 라이브 바카라 테이블

실시간 멀티플레이어 바카라 웹사이트입니다. **가상 포인트 전용이며 실제 결제·환전 기능은 없습니다.**

## 이번 수정 내역

- **[버그 수정] 뱅커 3번째 카드 규칙**: 플레이어가 6·7로 스탠드(3번째 카드 안 받음)했을 때, 뱅커 합이 4 또는 5면 원래는 드로우해야 하는데 코드가 드로우하지 않도록 되어 있던 오류를 수정했습니다. 실제 바카라 규칙과 다르게 판정되던 부분이라 게임 결과 자체가 틀리게 나올 수 있었습니다.
- **[버그 수정] 베팅 거절 시 UI 잠김**: 서버가 베팅을 거절해도(예: 다른 탭에서 잔액이 먼저 소진된 경우) 클라이언트가 이미 "베팅 완료" 상태로 화면을 잠가버려서 그 라운드 내내 재베팅이 불가능했던 문제를 수정했습니다.
- **[안정성] 종료 시 데이터 저장**: 배포 플랫폼이 재시작 신호(SIGTERM 등)를 보낼 때 마지막으로 한 번 더 유저 데이터를 저장하도록 추가해, 라운드 도중 재시작되며 방금 반영된 잔액이 유실될 가능성을 줄였습니다.
- **[정리] 불필요한 의존성 제거**: 서버가 실제로 쓰지 않는 `socket.io-client` 패키지를 `package.json`에서 제거했습니다.
- **[문서] Render 배포 가이드 보강**: 단계별 절차를 더 구체화하고, 무료 티어는 디스크가 영구 저장소가 아니라서 재배포/재시작 시 유저 데이터가 초기화될 수 있다는 점을 명확히 추가했습니다.

## 구성

- `server.js` — Express + Socket.io 백엔드. 서버가 딜러 역할을 하며 모든 접속자에게 같은 카드를 동시에 전송합니다.
- `public/login.html` — 회원가입 / 로그인 페이지 (아이디 중복 불가)
- `public/game.html` — 실시간 게임 테이블
- `public/admin.html` — 관리자 전용 충전 패널
- `data/users.json` — 계정/잔액 저장 파일 (서버 실행 시 자동 생성)

## 규칙 요약

- 8덱 슈, 2~9는 숫자 그대로 · 10/J/Q/K는 0 · A는 1, 합이 10 이상이면 뒷자리만 사용
- 베팅 10초 → 카드 공개 8초 주기로 자동 진행
- 메인 베팅(플레이어 1:1 / 뱅커 0.95:1 / 타이 8:1)은 필수, 페어 사이드 베팅(11:1)은 선택
- 타이가 나면 메인 베팅(플레이어/뱅커)은 환불, 페어 베팅은 각각 독립적으로 판정
- **셀프 충전 없음** — 가입 시 500P 지급, 이후 부족하면 관리자에게 요청해야 함

## 로컬에서 실행하기

```bash
npm install
cp .env.example .env
# .env 파일을 열어 JWT_SECRET과 ADMIN_SIGNUP_CODE를 자신만 아는 값으로 바꾸세요
npm start
```

브라우저에서 `http://localhost:3000` 접속 → 자동으로 로그인 페이지로 이동합니다.

### 관리자 계정 만들기

회원가입 화면의 "관리자 코드" 칸에 `.env`의 `ADMIN_SIGNUP_CODE` 값을 입력하고 가입하면 그 계정이 관리자가 됩니다.
관리자 계정을 만든 뒤에는 `ADMIN_SIGNUP_CODE`를 다른 값으로 바꾸거나 비워서, 아무나 관리자 코드를 알아내 가입하지 못하게 하는 것을 권장합니다.

관리자로 로그인하면 우측 상단에 "관리자 페이지" 링크가 뜨고, 여기서 유저별 포인트를 충전할 수 있습니다.

### 친구들과 같은 네트워크에서 테스트하기

같은 와이파이에 있다면, 서버를 실행한 컴퓨터의 내부 IP(예: `192.168.0.5`)로 `http://192.168.0.5:3000`에 접속하면 됩니다. `ipconfig`(윈도우) 또는 `ifconfig`/`ip a`(맥/리눅스)로 IP를 확인하세요.

## 인터넷에 실제로 배포하기 (Render 기준 상세 가이드)

로컬 PC만으로는 다른 사람이 인터넷을 통해 접속할 수 없습니다. Render.com의 무료 웹 서비스에 올리면 누구나 접속 가능한 주소가 생깁니다.

1. **GitHub에 코드 올리기**
   - GitHub에 새 저장소를 만들고 이 프로젝트 폴더 전체를 push 합니다.
   - `.gitignore`에 의해 `node_modules/`, `.env`, `data/users.json`은 자동으로 제외되니 그대로 두면 됩니다.
2. **Render에서 새 Web Service 만들기**
   - [render.com](https://render.com)에 가입 후 대시보드에서 **New → Web Service** 선택
   - 방금 만든 GitHub 저장소를 연결합니다.
3. **빌드/실행 설정**
   - Language/Runtime: Node
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Instance Type: Free로 시작 가능
4. **환경변수 설정 (Environment 탭)**
   - `JWT_SECRET` : `openssl rand -hex 32` 등으로 만든 무작위 문자열 (절대 남에게 공유 금지)
   - `ADMIN_SIGNUP_CODE` : 본인만 아는 임시 코드 (관리자 계정 만든 뒤 지우거나 다른 값으로 교체 권장)
   - `PORT`는 Render가 자동으로 주입하므로 따로 설정하지 않아도 됩니다.
5. **배포 & 관리자 계정 생성**
   - Create Web Service를 누르면 자동으로 빌드/배포가 시작되고, 완료되면 `https://프로젝트이름.onrender.com` 형태의 주소가 발급됩니다.
   - 이 주소로 접속해 회원가입 화면의 "관리자 코드" 칸에 방금 설정한 `ADMIN_SIGNUP_CODE`를 입력하고 가입하면 그 계정이 관리자가 됩니다.
   - 관리자 계정을 만든 직후, Environment 탭에서 `ADMIN_SIGNUP_CODE` 값을 비우거나 다른 값으로 바꾸고 **Manual Deploy → Deploy latest commit**으로 재배포해서, 이후 아무나 그 코드로 관리자 가입을 못 하게 막으세요.
   - 발급된 주소를 친구들과 공유하면 됩니다.

**Railway.app / Fly.io**도 비슷한 방식(Node.js 웹 서비스 + 환경변수 설정)으로 배포할 수 있습니다.

## 알아둘 점 (특히 무료 호스팅의 데이터 보존 관련 중요 사항)

- **Render 무료 티어는 디스크가 영구 저장소가 아닙니다.** `data/users.json`은 서버가 켜져 있는 동안에는 잔액을 잘 유지하지만, 코드를 다시 push해서 재배포하거나 Render가 인스턴스를 재시작시키면(무료 티어는 주기적으로 이런 일이 일어남) **파일이 초기화되어 모든 유저의 포인트가 사라질 수 있습니다.** 오래 운영하고 싶다면 Render의 유료 "Persistent Disk"를 연결하거나, 나중에 별도의 데이터베이스(예: Render Postgres 무료 플랜)로 옮기는 것을 고려하세요. 지금 구조에서는 완벽한 대비책이 없으니, 데이터가 날아가도 괜찮다는 점을 참여자들에게 미리 알리는 것을 권장합니다.
- 이 사이트의 포인트는 실제 화폐 가치가 없는 가상의 게임용 수치입니다. 참가자들 사이에서 포인트를 실제 돈이나 다른 대가로 교환하지 않도록 안내하세요.
- 무료 호스팅(Render 무료 티어 등)은 일정 시간 요청이 없으면 인스턴스 자체가 완전히 정지했다가 다음 접속 시 다시 켜지는 경우가 있어, 첫 접속이 수십 초 느릴 수 있습니다.
